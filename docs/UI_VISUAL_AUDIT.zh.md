# 全路由视觉审计

审计日期：2026-07-27

本文记录 Karkinos 完成各路由整页重构后的稳定视觉状态。`design.md` 继续是 UI
唯一 source of truth；本文只是验收快照和优先级边界，不是第二套设计系统。

## 范围与方法

审计使用正在运行的应用和本地持久化开发数据库，不注入 mock 财务数据，不联系行情
provider，也不触发券商、OMS、资本或订单提交权限。

整页审计覆盖：

- 公开首页 `/`；
- 总览、组合、账本、风控、Account Truth、决策、运营、行情、执行、回测、AI 研究和设置；
- 代表性持仓详情 `/portfolio/603659`。

视觉基线覆盖 1440 x 900、1280 x 800、834 x 1112 和 390 x 844；Latte 与 Mocha
均在桌面、平板和移动检查中实际运行。每个页面都等待 canonical GET 进入稳定证据状态后
再判断视觉层级。审计项目包括：

1. 首屏主角与五秒理解能力；
2. 页面构图和任务顺序；
3. 图表权重以及图表与证据的关系；
4. 列表—详情关系；
5. 桌面、平板和移动端重排；
6. 单一 H1、local overflow、默认披露状态和权限边界；
7. 缺失、过期、降级、阻断和已对账状态语言。

| 基线              | 稳定结果                                                                        |

| 1440 x 900，Mocha | 所有路由均保持单一可见 H1、文档与 shell 零横向溢出，以及稳定桌面信息层级。      |

主题对称、移动触控目标、reduced motion 和默认披露状态继续由确定性前端与 Playwright
contract 覆盖。页面初始出现 loading 或 missing 时，必须等 canonical GET 稳定后再判断；最终
缺失或过期证据仍必须显式展示并 fail closed。

## 优先级结论

本次审计没有发现 P0 或 P1 整页视觉缺陷。

以下只是观察触发器，不构成已授权修改：

- Trading：只有使用证据表明长期 0 待确认持续阻碍审计任务时，才重新评估空队列；一旦存在
  pending confirmation，队列必须继续是首屏主角。
- AI Research：只有出现持久化复核任务后，才重新评估桌面空状态平衡；禁止用概念研究或 mock
  内容填充空间。
- Settings：只有 operator 测试证明渐进披露仍不足时，才考虑拆分导航；禁止为了缩短页面再造
  routine panels。

按钮大小、边框、时间格式、badge 打磨等局部细节继续低于当前优先级。只有出现首屏层级失败、
阻断被隐藏、图表—列表关系失败、跨端不一致、权限歧义、canonical 状态冲突、可访问性回归或
overflow 时，才恢复 UI 修改。

## 完整性与权限结果

审计没有发现需要修改金融契约的 UI 路径。所有被审页面继续消费 canonical persisted
projections；读路径不联系 provider、不写库；UI 不重算价格、成本、P&L、风险、配置或权限；
缺失和过期证据继续显式展示。策略与 AI 不获得券商权限，Trading 继续默认人工确认，且无默认
submit、cancel、自动恢复或资本扩容能力。
